# Everyday Arabic dialogue: what the verifier can and cannot check

Math and logic word problems are not what Arabic users type into an assistant.
This track extends FalconVerifier towards everyday dialogue with three layers,
each honest about what Lean is actually deciding.

```
Arabic dialogue turn
  → split into  fact premise | inference | chat
  → inference: deterministic everyday fragment (arabic_daily.py)  or  LLM formalizer
  → Lean 4 proposition  → kernel verdict  → faithfulness audit
  → verified / refuted / unknown / ill_formed / unverified_premise / skipped
```

## Layer 1 — deterministic everyday fragment (`falconverifier/arabic_daily.py`)

Fail-closed clause grammar over dialogue text (speaker labels such as
«العميل:» are stripped, extra context clauses are tolerated). Each match yields
a Lean proposition **and** a derivation certificate; nothing is guessed — any
unrecognised clause returns `None` and the LLM formalizer takes over.

| family | example | Lean shape |
|---|---|---|
| weekday | اليوم الخميس، والرحلة بعد ١٢ أيام. ما اليوم بعد ١٢ أيام؟ | `((4:ℕ) + 12) % 7 = 2` |
| clock | بدأ الاجتماع في الساعة ٩:٣٠ واستمر ساعتين و٤٥ دقيقة. في أي ساعة انتهى؟ | `((9:ℕ)*60 + 30 + 165) = 12*60 + 15` |
| currency | ١ دولار = ٣٫٧٥ ريال. كم ريالاً يساوي ١٥٠ دولاراً؟ | `150 * 3.75` with decimal tolerance |
| unit | ١ كيلومتر = ١٠٠٠ متر. كم متراً في ٣٫٥ كيلومتر؟ | same |
| bill | الفاتورة ٢٤٠ درهماً، تضاف ضريبة ٥٪ ورسوم خدمة ١٠٪، وتقاسمها ٣ أشخاص | `240*(1+5/100)*(1+10/100)/3` |

Lean integration test: `tests/test_lean_integration.py::test_everyday_arabic_fragment_props_decide`
(gold answers verified, wrong answers refuted for all three shapes). Across the
64 deterministic benchmark items, every gold answer is `verified` and every
perturbed answer `refuted` (no `unknown`).

## Layer 2 — premise / inference split (`unverified_premise`)

The formalizer labels a CoT step that asserts world knowledge not given in the
problem ("مكة في السعودية", a price, a visa rule) as `kind: fact`. Such steps
are never encoded as Lean propositions: the verifier returns
`Verdict.UNVERIFIED_PREMISE`, they are excluded from the assurance denominator,
and the UI shows them as "premise, not for Lean". Only the inference drawn
from the premise is checked. Pure chit-chat stays `skipped`.

## Layer 3 — everyday Arabic dialogue benchmark

`bench/problems_daily_ar.jsonl` — 116 items, generated by
`bench/make_dataset_daily_ar.py`, labelled `inference` (94) / `fact` (12) /
`chat` (10); scenarios: customer service, shopping, scheduling, travel, family.

### Deterministic coverage (`python bench/daily_coverage.py`)

```
bill 18/18 · clock 12/12 · currency 12/12 · unit 10/10 · weekday 12/12

fact/chat items formalized by the deterministic layer: 0 (must be 0)
```

contradiction, conditional promises) go to the LLM formalizer.

### What this run teaches

* **Detection on the deterministic families is 28/30 (93%)**, with zero false
  alarms after the extraction fix — this is where the everyday layer earns its
  keep. The student rarely *repairs* weekday/clock answers, so the fix rate is
  low: the feedback for these fragments is still generic arithmetic text and
  should be rendered as Arabic ("ابدأ من الخميس وعدّ ١٢ يوماً…").
* **Kinship and appointment conflicts are the honest gap.** The 34B formalizer
  wrote unary-predicate syllogisms for «أخو أبي» (Lean verified a wrong answer
  twice) and `16:00`-style literals for time intervals (`ill_formed`). Both need
  deterministic fragments (a finite kinship algebra; interval overlap over
  minutes) rather than better prompting. Until then a `verified` from an LLM
  translation is only as trustworthy as the translation — the UI marks the
  provenance (certificate vs LLM).
* A ℚ-lift artifact was caught by this run: `((2:ℚ)+7-4) % 7 = 0` is provable
  in Lean, so a wrong weekday answer was `verified`. `lift_to_rat` now refuses
  propositions containing `%`/`∣` (regression test in `tests/test_units.py`).
* Batch probing all 64 items × {gold, wrong} exposed Lean's default
  `maxErrors = 100`: after 100 errors the compiler exits and the remaining
  claims looked "both proved" (mapped to `unknown`). The runner now passes
  `-DmaxErrors=100000` (regression test in `tests/test_lean_integration.py`);
  with it all 64 gold answers are `verified` and all 64 wrong answers `refuted`.
* `unverified_premise` fired on 19 CoT steps in this run without any of them
  being reported as an error — the fact/inference split works end to end, but
  the fact-only items (12) and chat items (10) are not yet part of the model
  run; they are covered by the leakage check only.
