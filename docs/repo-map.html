NYU Falcon repo map

What runs where when NYU Falcon is deployed, how to deploy it, and where each part of the code lives. The website is new; the verification engine under it is the same code as before.

Where it runs

Everything that needs a secret or Lean runs in the app container on your server. The browser only downloads the site and talks to that server; it never sees the Falcon key. The built site ships inside the image, so there is no separate frontend to deploy.

Deploy it

  1. Wait for the Docker image workflow on main to finish (Actions tab, about 15 minutes). It publishes ghcr.io/hw4375-collab/falconverifer:latest with the new site inside.

  2. Make that package public (GitHub, Packages, falconverifer, Change visibility), or run docker login ghcr.io on the server with a read-only token.

  3. Get an Ubuntu 22.04 or 24.04 server with at least 4 vCPUs, 8 GB RAM and 40 GB disk. Open ports 80 and 443 and point a DNS A record at it. Without a domain, 1-2-3-4.sslip.io works for IP 1.2.3.4.

  4. On the server, run the installer once. It installs Docker, clones the repo to /opt/falconverifier, creates deploy/.env.production and stops.

  5. Edit /opt/falconverifier/deploy/.env.production: set DOMAIN and FALCON_API_KEY. For a private demo, also set FV_ACCESS_TOKEN.

  6. Run the installer again with FV_IMAGE set. It pulls the image, starts the app and Caddy, waits for the health check and prints the URL.

  7. Open https://DOMAIN/healthz. When lean_project and falcon_key are both true, the demo answers live questions.

# step 4, then edit deploy/.env.production (step 5)
curl -fsSL https://raw.githubusercontent.com/hw4375-collab/FalconVerifer/main/deploy/install.sh | sudo bash
sudo nano /opt/falconverifier/deploy/.env.production

# step 6
cd /opt/falconverifier
sudo FV_IMAGE=ghcr.io/hw4375-collab/falconverifer:latest bash deploy/install.sh

# updating later: push to main, wait for the image, then on the server
cd /opt/falconverifier && git pull
sudo FV_IMAGE=ghcr.io/hw4375-collab/falconverifer:latest bash deploy/install.sh

How the code fits together

New with the website Changed for the website Unchanged

The browser only ever talks to server.py. It serves the built site from falconverifier/static/ and runs the engine for live questions. Recorded runs never touch the engine: their traces in bench/results/ are exported to static JSON, so the site also works with no server behind it.

One live question, step by step

  1. The Demo page posts the question to /api/solve/stream (web/src/lib/stream.ts).

  2. server.py waits for a free Lean worker and starts the loop in agent.py.

  3. student.py sends the question to Falcon through llm.py and parses the numbered steps and the final answer.

  4. formalizer.py turns each step into a Lean proposition. A deterministic Arabic fragment (arabic*.py) handles it when one matches; otherwise the Falcon-H1-Arabic 34B formalizer writes it and a faithfulness audit checks it.

  5. verifier.py and lean_runner.py compile the propositions in lean/ and try to prove each one and its negation.

  6. feedback.py turns a refutation into a correction for Falcon. The loop runs up to 3 rounds, and memory.py reuses verdicts and translations it has seen before.

  7. Every step streams back as a server-sent event, and stream.ts updates the two answer cards: Falcon alone, and Falcon with Lean.

Running it

# the site and the API on http://localhost:8000 (the built site is committed)
pip install -e . && falconverifier serve

# working on the site
cd web && npm install
npm run dev      # http://localhost:5173, API proxied to :8000
npm run data     # after a new benchmark run
npm run build    # writes falconverifier/static

Live questions need FALCON_API_KEY and a built lean/ project. Without them, the demo replays recorded runs.
